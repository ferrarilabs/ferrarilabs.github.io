## Notas de leitura da matriz

- RM-006/RM-007 são os dois riscos de maior score (15, ALTO) — ambos são **achados confirmados
  empiricamente nesta auditoria**, mas **consistentes com a decisão de produto já documentada**
  ("bolão transparente"), não configurações acidentais. Ver `SECURITY_ASSESSMENT_REPORT.md` para
  o veredito consolidado.
- RM-015 (mass assignment de propriedade admin) é o risco mais acionável de curto prazo — score
  10 (ALTO) e é o único item desta lista onde uma mitigação parcial (endurecer `WITH CHECK`) é
  possível **sem** esperar por um backend completo.
- Itens N/A (RM-008, RM-009, RM-010, RM-012, RM-016, RM-028) são marcados como tal
  explicitamente, não omitidos — confirma que a ausência de JWT/Auth real foi verificada, não
  presumida.
- RM-031 é diferente de todos os outros itens desta matriz: não é um risco inferido por análise
  de policy/código — é uma exposição **já confirmada e já ocorrida** (PII real de 15
  participantes em um script committed a um repositório público há semanas). Tratado como ALTO
  apesar do impacto "só" moderado (PII de contato, não financeiro) porque a probabilidade não é
  uma estimativa — é 100% certa, já aconteceu. Ver `SECURITY_RISK_REGISTER.md` SR-15.
